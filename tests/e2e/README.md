# tests/e2e

端到端测试：验证用户链路与故障降级。默认全部使用 Fake Provider，CI 中不需要任何外部凭据；真实平台的验证属于 Gate E1 spike，不放进普通 CI。归入 Merge Gate。

## 两条主线

**主线一 · 全链路**（Fake Provider）

```text
创建工作空间 → 读取规划条目 → 打开工作项 → 开始工作
→ 工作树/分支 → 变更请求 → 流水线运行 → 交付投影
```

**主线二 · 故障注入**（每条都必须证明"局部降级、不崩溃"）

| 故障 | 期望 |
|---|---|
| 规划 Provider 离线 | 保留最后已知状态并标记陈旧，禁止外部写入 |
| 开发 Provider 离线 | 规划仍可用，"开始工作"降级 |
| 交付 Provider 离线 | 交付视图显示未知，规划与研发不受影响 |
| 执行环境不可用 | 降级为人工执行，保留工作树与分支 |
| 权限被撤销 | 相关能力实时降级为只读，不隐藏错误 |
| 重复 / 乱序事件 | 不产生重复实体，旧观察不覆盖新观察 |
| 客户端重连 | 按版本缺口重新拉取，不出现身份漂移 |

## 验收方式

端到端失败信息必须能指向**具体的不变量**（例如"成员关系与内容身份分离"），而不是只报"页面断言失败"。
