### #239 的 P2 证据

文档回读例子用 `node ... | grep ...`，后文要求退出码 0。仓库外临时 `.mjs` 含 `test('probe', () => {})` 与 `process.exitCode = 7`，按同一 Node 参数直接执行为退出码 7，按文档管道执行为退出码 0，输出仍是：

```text
✔ probe
ℹ tests 1
ℹ fail 0
```

建议先保存 Node 的退出状态，再过滤输出，或在复制用的脚本中启用 `pipefail`；负对照仍须零匹配。作者此次 72 组验证使用独立进程检查真正退出码，结果有效；因此此项是未来使用例子的假绿风险，列 P2。

### #240 的 P2 证据

在 head 的公开 `migrate` 上提供一个同能力数据库包装器：从 [1,2,3]、观察表为空的库开始；005 的事务外预检已通过后，在第一个 `exec('BEGIN IMMEDIATE')` 之前让第二个连接按旧端口编码插入 `v9`。随后调用真实 `db.exec`、继续真实迁移。结果：

```json
{"afterExternal":[1,2,3],"after":[1,2,3,4],"error":{"name":"LegacySourceVersionError","unchangedClaim":true}}
```

005 事务内复判确实拒绝并回滚，但它不能撤销已提交的 004。现有 U6 直接调用 005 的数据步骤，只证明该步骤拒绝旧值，未覆盖整个迁移序列的这个窗口。建议区分预检失败与事务内失败的错误承诺，记录实际已提交版本 / 恢复状态，或扩大锁范围使承诺成立，并补完整 `migrate` 交错用例。没有观察丢失、005 未误记账，004 仍是已成功的独立迁移，因此列 P2。
