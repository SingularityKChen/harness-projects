### 行为缺陷的独立复现

主控在独立检出上复跑了子评审要定为 P2 的两条行为缺陷：

- `decode.ts:79`：先成功同步，再把一个条目的单选值改成 `optionId: null`，`bootstrapWorkspace` 返回 `ok: false / unavailable`，全部行标 degraded、保留最后已知值；条目不改则重试永远不成功。对照 `name: null` 正常同步。base 不取 `fieldValues`，没有这个失败面——本 PR 新增。方向是 fail closed，所以不阻塞。
- `work-item-list-view.ts:115`：只删去 `&& nativeName`，全量 contract + integration + e2e 1172 / 1172 仍绿；变异后每个无映射的行会显示「undefined（未映射）」。

同步覆盖 Host 写入一条在 base / head 上用同一脚本对照：base 上 GitHub 路径覆盖成 unknown、fake 路径覆盖成 todo / in_progress / done，head 上 GitHub 路径覆盖成映射值。可达性 main 既有，本 PR 只改变了覆盖值，定 P2；需要一个同仓 issue 承接语义裁决（与「移除映射后不留旧状态」冲突）。

#269 的 fixture scope 门由主控读码确认：第 60 行在路由为 `undefined` 时回退到场景工作区，跨工作区时列表照样渲染当前 read，第 63 行的 href 用了路由里的外来 `projectId`。单用户下不构成越权，但 fixture 是 #229 挂载的样板。
