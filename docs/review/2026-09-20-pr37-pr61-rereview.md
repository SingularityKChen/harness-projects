## Design / Spec

复评使用 First Principles Development 的 audit/review stage，并用 Qian Systems Router 检查：

1. 事件是否只是唤醒信号，而不是状态真值；
2. PAT 是否只接触默认分支可信代码；
3. artifact / snapshot / mutation ack 是否形成可验证的目标绑定和确认链；
4. fail-closed 是否真的覆盖传输、结构、完整性和缺失输入，而不是仅靠测试绿灯。

## Surprises & Discoveries

1. **“默认分支可信执行”解决了代码执行面，但没有自动解决输入完整性。** #37 已正确把 PAT 从 PR head 移到默认分支；artifact 仍是跨权限边界的数据输入，必须验证它与触发 run 的目标关联。
2. **`continue-on-error` 把 fail-closed 链条重新打开。** 脚本自身的 GraphQL、JSON、snapshot、ack 校验均会失败退出，但 workflow 在 artifact 下载层把失败变成成功 no-op，局部正确性没有传递到系统结果。
3. **#61 的离线纯函数与 live adapter 边界已收敛。** 当前没有复现上轮 add/add 冲突或“全绿但零检查”路径；剩余风险是运行时部署后的可观测性，而不是当前代码契约。
