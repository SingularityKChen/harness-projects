## Surprises & Discoveries

- 修复本身引入了第一轮复评的 P2：只按错误码区分「确定 / 不确定」不够，真实 provider 的错误映射会把「此刻读不到」报成 `not_found`。根因在「有缺口的 Ready 能被改判 Failed」这个入口，堵住入口比修分类更稳。
- 一次未提交就跑的变异批，用 `git checkout --` 抹掉了刚写的重构；变异前先做 WIP 提交并断言工作树干净。

- 四路子评审在约 20 分钟时同时因 API 流中断而停止，各自的检出都没有遗留改动（只有 storage 那一路停在「生产代码切到 base」的中间态，由主控还原），用 SendMessage 恢复后都完成了。
- 本机有一个属于更早会话的孤儿 `node --test` 进程，挂了约 23 小时；它的工作目录在那个会话的临时目录里，很可能就是 TD-010 描述的替身事务死锁。这说明 TD-010 的「`test` 脚本没有 `--test-timeout`」不只是理论风险。
- PR #253 的 `ambiguous_result` 路径与它自己写进 ExecPlan 的 B-3 承诺（run 状态未知顶层报 Unknown）相矛盾，但 base 上逐字相同，所以按既有缺陷处理。
