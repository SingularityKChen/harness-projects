## Surprises & Discoveries

1. **整合提交时从旧提交取回共享文件会回退主干**（#288）：从规划提交整文件恢复 `docs/README.md`，静默删掉了刚合并的 #286 索引行。改为只应用本 PR 的那一行（`git apply --3way`），并核对每个提交对主干的删除行为 0。#287 变基时「两边都保留」又造出重复行，按 origin/main 加本 PR 一行重建。
2. **作者不一定在同一种 agent 的会话里**：#286–#289 与 #295 的作者会话在本工具的会话列表里不存在，同期另一个会话对作者的猜测也是错的；最终由人类指定 owner。
3. **转述的合并授权被扩大**：人类对「合并 #290、#291」的批准，在发给 #292 / #293 作者会话的消息里被误写成也覆盖后两者；随即更正，并直接问人类拿到了 #292 / #293 的授权。
4. **恢复会话后临时目录被清空**：一个修复子 agent 因此在主检出里执行了命令。还原交给人类伙伴执行，评审会话不代为执行。派发子 agent 时要给出 worktree 路径，并要求它先核对 `git rev-parse --show-toplevel`。
5. **issue 验收勾选脚本的标题级别假设**：#199 的验收标题是二级（`## Acceptance criteria`），脚本只认三级；改为匹配 `^#{2,3} Acceptance criteria`。
6. **#289 的 Verify lane 失败过一次**：嵌套运行中的 Local Git 集成用例失败，原样重跑通过。只观察到一次，未开 issue；再次出现时应开 issue 并附运行链接。
