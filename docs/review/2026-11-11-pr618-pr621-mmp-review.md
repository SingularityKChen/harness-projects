## Purpose / Big Picture

判断每个 PR 能否独立验收、合入和回滚；本地/托管测试与安装、人类产品及 R1 接受分别记录。P0/P1 必须 REQUEST_CHANGES 并交现有实现 owner；只有非阻塞项时按用户本会话直接授权修复、独立复评和 rebase 合入。

## Context and Orientation

逐 PR 的不可变锁定事实、P0/P1/P2/P3 风险矩阵和实际反例分别位于各自工作树的 `docs/review/pr-618-mmp-review.md`、`pr-619-mmp-review.md`、`pr-620-mmp-review.md`、`pr-621-mmp-review.md`。#618 关联 #617；#619 关联 #597；#620 关联 #606；#621 关联 #607。#620 → #621 是原生 stack #622，其余独立。

## Design / Spec

采用按权限安全、数据持久链、UI 产品闭环分工的独立评审，再独立检查组合；不把 CI 绿色替代产品结果。三位子评审使用 gpt-6.1-sol-hc/high，分别负责 #619、#618/#620、#621；主审统一检查会话归属、GitHub 事件、现有 issue、顺序接合与发布门。先建全级别矩阵再审代码，全部发现按 PR 一次提交。普通日历周保持与权限撤回严格区分，设计取舍需由合同和反例判定，不能凭偏好报缺陷。

## Global Constraints

仅评审/必要修复四个 PR；一个架构单元一个写入 owner。评审/批准 actor 为 Singularity-AI-Bot（`gh-review`），开发、提交、作者回复、resolve 和合并 actor 为 SingularityKChen（`gh`/git）。外部写入目标是本仓库 GitHub 管理面，无产品 ProviderBinding。按 PR 编号/分支定位同一对象幂等更新。

保留主工作区及其他工作树。评审记录留在各 PR 自己工作树，运行态仅在忽略目录或仓库外临时检出。共享历史整理前保留 `refs/backup/pr<N>-before-mmp-review-20261111`，精确 lease 发布。只使用 `merge_method=rebase`；Status 与原生依赖未获授权，不写入。

## Plan of Work

### Batch 1 · 独立风险评审

锁定四个 PR head/base、全部线程分页、真实 checks、原生 stack 与实现会话；全矩阵审查代码、产品结果、架构、失败反例、测试、issue 和设计。各 PR 一次提交完整 review：P0/P1 为 REQUEST_CHANGES；其余 APPROVE。现有 owner 通过会话列表及实际消息确认，不能只按作者推断。

### Batch 2 · 当前版本接合与收尾

工程顺序为 #618 → #619 → #620 → #621；只表达接合次序，不创建规划依赖。每个前项合入后，后项从真实 main 重新接合，重新锁定 head/base、代码树、checks、线程、issue 和当前批准。原生栈成员使用异步合并端点与预期 head。已完成实施计划位于 completed；本轮追加授权和评审证据，最终保留交付物级提交。

**验证**：在各 `fix/code-scanning-hardening`、`fix/private-host-data`、`feature/source-schedule`、`feature/planning-timeline` 分支工作树执行对应单 PR 记录的命令。组合在仓库外临时 clone 依次 rebase 四个已锁定 head；执行 `pnpm install --offline --frozen-lockfile`、`pnpm verify`、`pnpm test:browser`、`pnpm run boundaries`、`node scripts/workflow-check.mjs`，期望退出 0。逐最终发布树运行 `node scripts/rule-checks.mjs disclosure <base>`、`node scripts/rule-checks.mjs size <base>` 与 `git diff --check <base>...HEAD`；对文档新增链接做存在性检查。远端用 `gh pr view <N> -R SingularityKChen/harness-projects --json state,headRefOid,baseRefOid,baseRefName,mergeable,mergeStateStatus,statusCheckRollup,closingIssuesReferences,mergeCommit` 及 GraphQL 全线程/issue 反向关联回读。
